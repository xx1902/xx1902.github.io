常见 Decoder-only Transformer

  1. 输入Tokenizer / Embedding

    文本 → token ID → 隐状态

  2. 重复 N 层Attention + MLP

    归一化、位置编码、因果掩码与残差

  3. 输出LM Head

    隐藏状态 → 词表 logits

  4. 生成循环采样 → 下一个 Token

    更新序列，进入下一轮 Decode

能力适配与反馈优化

  1. 基座预训练模型

    先固定模型版本与基线

  2. 监督信号SFT / LoRA / QLoRA

    训练目标与参数更新方式是两个维度

  3. 可选后训练偏好 / 奖励优化

    RLHF、PPO、GRPO 等路线分别验证

  4. 闭环评测与部署

    质量、安全、泛化、资源与延迟

并非所有模型都必须经过这些步骤；蒸馏是另一种训练信号来源，投机解码则是推理时的执行策略。

视觉语言表示到动作

  1. 观察与目标图像 + 语言指令

    部分实现还接收机器人状态或历史

  2. 感知与融合视觉编码 / VLM

    形成视觉与语言的联合表示

  3. 动作建模VLA / 动作头

    输出动作 token、连续动作或轨迹

  4. 环境闭环执行 → 新观察

    控制、安全约束与任务成功率

模仿学习与强化学习是可选训练路线，不是所有 VLA 的必经步骤。VLT 的具体含义待确认，不据此推导模型结构。

我当前适合怎样准备

  • 先补基础：Linux、C++ / Python、计算机体系结构、并行计算和 Transformer 生成链路。LoRA 自评为掌握，不意味着同时掌握推理系统。
  • 主线建议：AI Infra → 推理优化。以 vLLM 或 llama.cpp 中的一个可定位问题为起点，保留版本、负载、剖析、改动与回归测试。
  • 辅助线：把 Agent 的调用链作为实际工作负载，区分模型耗时、工具耗时和应用层排队。
  • 分布式线：有多卡资源后再做通信与并行扩展实验；资源不足时先学习机制，不编造多卡结果。
  • 投递材料：一页简历、代码仓库、可复现实验报告、问题复盘。每项结论能对应到日志或测试。

薪资、SP 与 SSP 怎么记录

“薪资分布”需要同一年、同地区、同岗位、同身份的样本。当前没有个人 offer 或可信的同口径样本，因此不在这里填一个看似精确的市场范围。

部分校招讨论把 SP / SSP 用作高于常规档的 offer 称呼，但它们不是跨公司统一等级；不能仅凭名称判断薪资、职级或录用门槛。也不要把实习日薪和校招年包混在一起。

记录维度 应向招聘方确认
身份与时间 实习 / 校招 / 社招，批次、年份、城市、岗位、团队
现金 税前月薪、保证发薪月数、绩效奖金的条件与波动
一次性项目 签字费、搬迁补贴，发放条件与返还条款
长期激励 股票 / 期权、估值口径、归属期、流动性，不当作确定现金
实习条件 日薪、计薪天数、住宿餐补、时长与转正流程
机会质量 真实工作内容、导师、代码所有权、算力资源与成长空间

比较时把“保证现金”“不确定奖金”“长期激励”分别列出。岗位方向比 SP / SSP 标签更能帮助判断日常工作是否匹配。具体金额、合同和税务问题应再核对正式文件。
